════════════════════════════════════════════════════════════════
  Edu-RAG-Tutor 问题总结：应用内发消息"没反应"（v1.2.1 修复）
════════════════════════════════════════════════════════════════

【问题现象】
- 用户在应用窗口发送学习消息后"没有反应"：自己的气泡能显示，
  但没有任何"思考中"提示、没有回复、没有报错弹窗。
- 换模型（deepseek-v4-flash → deepseek-chat）无效。
- 直接用 API/curl 调后端 /api/chat 一切正常，问题只出现在界面操作。
- 时间线：v1.0（第一版）交互正常秒回；v1.1 起逐渐"没反应"，
  v1.2.0 后用户感知为完全失效。

────────────────────────────────────────────────────────────────
【根因一（主凶）：前端悬空引用，所有应用内发送 100% 静默失败】
────────────────────────────────────────────────────────────────
- 位置：static/js/app.js → setStreamingUI() 函数。
- 来源：commit 3a31512（v1.1 语音输入功能，麦克风按钮替换回形针
  上传按钮）。该提交删除了：
    - els 定义中的 uploadBtn: $('upload-btn')
    - DOM 中的上传按钮元素
  但漏删了 setStreamingUI() 里的一行：
    els.uploadBtn.disabled = on;   // ← els.uploadBtn 已不存在
- 崩溃链路：onSend() 先渲染用户气泡 → 调 streamChat() →
  第一行 setStreamingUI(true) 抛 TypeError
  （Cannot set properties of undefined (setting 'disabled')）。
- 为什么毫无提示：
  1) 抛异常位置在 streamChat 的 try 块【之外】，catch 接不住，
     控制台才可见，界面无任何反馈；
  2) state.streaming = true 在抛异常前一行已执行 →
     后续每次点发送都被 onSend 入口守卫
     （if (!content || state.streaming) return）静默拦截。
- 结论：从 v1.1 起，应用内每条消息都在发请求前崩溃，
  且第一次失败后整个窗口的发送功能永久瘫痪（直到刷新页面）。

────────────────────────────────────────────────────────────────
【根因二（帮凶）：服务随窗口关闭而退出，造成"断联"假象】
────────────────────────────────────────────────────────────────
- app/main.py：webview 窗口关闭 → webview.start() 返回 →
  os._exit(0) 强制退出整个进程（uvicorn 是守护线程随之死亡）。
- 开发模式下误关黑色控制台窗口同样会杀死服务。
- 服务退出后，页面若还开着，发消息会失败且错误 toast 一闪而过，
  表现同样是"没反应"。排查过程中服务共意外退出 3 次，
  混淆了对主凶的定位。

────────────────────────────────────────────────────────────────
【修复内容】
────────────────────────────────────────────────────────────────
1. 删除 setStreamingUI() 中悬空的 els.uploadBtn.disabled = on;（核心修复）
2. streamChat 的 catch 增强：toast 带具体错误信息，并在聊天区追加
   持久化的错误系统卡片（此前 toast 一闪而过容易被忽略）；
   静态资源版本号提升 js?v=17 强制刷新缓存。
3. 启动脚本增加输出重定向到日志文件（%TEMP%\eduragtutor 运行日志），
   便于后续排查。
4. 版本号升级 1.2.0 → 1.2.1（installer.iss / build.bat / README）。

────────────────────────────────────────────────────────────────
【排查方法记录（复盘用）】
────────────────────────────────────────────────────────────────
1. netstat 查端口 8760 监听 → /api/health 探活 → 排除服务死亡。
2. curl 直接 POST /api/chat 实测 SSE 全链路 → 后端无责。
3. 查会话消息时间戳：用户消息不在数据库 = 请求从未到达后端
   → 锁定前端。
4. 真浏览器复现（关键一步）：Enter 键触发 onSend 后气泡已渲染，
   但 Network 面板无任何 POST /api/chat 请求 → 前端在发请求前崩了
   → Console 抓到 TypeError at setStreamingUI。
5. git log -S "els.uploadBtn.disabled" 定位引入提交。
教训：前端静默吞错误（异常点在 try 外 + 入口守卫）会让"网络问题"
"服务挂了""模型太慢"等假象掩盖真凶；关键路径的状态变更和报错
必须在 UI 上可见。E2E 测试必须走真实界面，不能只测 API。

────────────────────────────────────────────────────────────────
【遗留问题（暂未修复，不影响学习功能）】
────────────────────────────────────────────────────────────────
1. 窄窗口（<600px）布局挤压时，右侧栏面板会遮挡顶部按钮
   （📒🎯⚙️🕘），点击无效；拉宽窗口即可。
2. "关窗口 = 服务退出"的设计对开发模式不友好，可考虑
   服务与窗口分离或退出前二次确认。
